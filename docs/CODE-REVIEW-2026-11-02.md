## 3. BLOCKER (падение/полная неработоспособность в штатном использовании)

### F-A1. Структура `PrinterInfo2` не соответствует `PRINTER_INFO_2W`: пропущены 2 указателя
- **Файл:** `src/Picket302.Printing/Devices/PrinterManager.cs:665-724` (структура), `:91-104` (чтение буфера)
- **Код:** после `Datatype` (11-й указатель) сразу `Attributes` — нет `pParameters` и `pSecurityDescriptor`.
- **Суть:** на x64 `Marshal.SizeOf<PrinterInfo2>()` = 120 вместо 136 байт. Индексация буфера
  (`буфер + i*размер`) читает со смещением +16 байт на каждый следующий принтер — мусорные
  `IntPtr`, `Marshal.PtrToStringUni` даёт AccessViolation (необрабатываемое падение процесса).
  Даже для первого принтера `Attributes` читается с младших 32 бит `pParameters`, а `Status` —
  фактически `Priority` (=1) → `ОпределитьСостояние(1)` попадает в бит OFFLINE (см. F-A6) —
  любой готовый принтер отображается «вне сети». Путь используется в основном UI (MainShell.cs:3297) и COM.
- **Исправление:** добавить в структуру перед `Attributes` поля `IntPtr Parameters;` и
  `IntPtr SecurityDescriptor;` (13 указателей + 8 DWORD = 136 байт); закрепить тестом `Marshal.SizeOf<PrinterInfo2>() == 136`.
- **Уверенность:** 95%

### F-A2. `GdiGraphicsContext.DrawStringMm`: порядок Scale→Translate — начало координат умножается на масштаб
- **Файл:** `src/Picket302.Printing/Rendering/GdiGraphicsContext.cs:74-81`
- **Код:** `_графика.ScaleTransform(масштабX, масштабY); _графика.TranslateTransform(xMm, yMm); ... DrawString(text, шрифт, кисть, 0f, 0f, ...)`
- **Суть:** GDI+ по умолчанию `MatrixOrder.Prepend`: итог `W = S×T`, точка (0,0) → `(масштабX·xMm, масштабY·yMm)`.
  Шрифт создаётся кеглем 100pt и «подгоняется» масштабами ≪1 (напр. 4мм/45мм ≈ 0,09) → весь
  подогнанный текст (адресные строки конверта, цифры кодового штампа) «схлопывается» к левому
  верхнему углу и на печати, и в предпросмотре. Юнит-тесты используют фейковый `IGraphicsContext` — не ловят.
- **Исправление:** поменять порядок: сначала `TranslateTransform(xMm, yMm)`, затем `ScaleTransform(...)`.
- **Уверенность:** 88%

### F-A3. `ReadDevMode` выделяет 220 байт без запроса фактического размера DEVMODE — порча нативной кучи
- **Файл:** `src/Picket302.Printing/Devices/PrinterManager.cs:166-192`
- **Код:** `размер = Marshal.SizeOf<DevMode>()` (=220); `AllocHGlobal(размер)`; `DocumentPropertiesW(..., буфер, ..., DM_OUT_BUFFER)`
- **Суть:** драйвер записывает `dmSize + dmDriverExtra` байт; у реальных драйверов (HP/Canon/Epson/Kyocera)
  `dmDriverExtra` — сотни байт → запись за концом буфера, повреждение кучи. Вызывается из
  `GetDeviceInfo` в **каждой** печатной сессии с реальным принтером. Проявляется случайными
  падениями процесса, не связанными по стеку с печатью.
- **Исправление:** сначала `DocumentPropertiesW(..., IntPtr.Zero, IntPtr.Zero, 0)` → требуемый
  размер; выделить по нему; маршализовать только первые `SizeOf<DevMode>()` байт.
- **Уверенность:** 85%

### F-A4. Фильтр чётности в спулере: неотобранные страницы выводятся пустыми листами
- **Файл:** `src/Picket302.Printing/Devices/SystemDrawingPrintSpooler.cs:84-115` (особенно 96-99)
- **Код:** `if (!отобранныеСтраницы.Contains(номерСтраницы)) { событие.HasMorePages = !последняя; return; }`
- **Суть:** `StartPage` вызывается до `PrintPage` — каждая итерация цикла это физический лист.
  Двухпроходная печать (ТЗ §8.6 ф.86, основной сценарий для принтеров без дуплекса) даёт
  чередование «конверт, пустой лист, конверт, пустой лист…»; «только чётные» для одностраничного
  задания выдаёт один пустой лист (выборка пуста, но PrintPage срабатывает минимум раз). Дуплексный
  вывод испорчен, бумага перерасходована.
- **Исправление:** построить очередь `отобранныеСтраницы` и в обработчике брать очередной номер
  из неё (`context.CurrentPage = очередь[i]`, `HasMorePages = остались элементы`); при пустой
  выборке не вызывать `документ.Print()` вовсе.
- **Уверенность:** 85%

### F-B1. SMTP 334/354 трактуются как отказ — авторизация и DATA не проходят ни на одном реальном сервере
- **Файл:** `src/Picket302.Infrastructure/Mail/SmtpClientFacade.cs:21, 661-672, 756-776` — **ПОДТВЕРЖДЕНО супервизором**
- **Код:** `public bool IsSuccess => Code is >= 200 and < 300;`; `AUTH PLAIN` → 334 → «не успех» →
  фолбэк LOGIN → 334 → «Ошибка авторизации»; `DATA` → 354 → «Сервер отклонил передачу данных».
- **Суть:** по RFC 5321/4954 334 — challenge авторизации, 354 — приглашение к телу письма.
  Электронная рассылка (ф.92-100) неработоспособна с любым настоящим SMTP-сервером. Тестов с
  эмулятором SMTP нет — 1113 зелёных тестов дефект не ловят.
- **Исправление:** для AUTH принимать 334 как «продолжать» (отправлять токен/логин); для DATA
  ожидать 354 и только после «.» требовать 2xx (метод `ВыполнитьОжидаяКод(int expected)` или
  точечные проверки `ответ.Code == 334` / `== 354`).
- **Уверенность:** 97%

### F-B2. Прокси: TCP подключается напрямую к SMTP-серверу, HTTP CONNECT пишется в этот же сокет
- **Файл:** `src/Picket302.Infrastructure/Mail/SmtpClientFacade.cs:1210-1239, 1397-1430`
- **Суть:** адрес прокси (`WebProxy.Address`) не используется для подключения; при Enabled
  соединение идёт в обход прокси, а `CONNECT {_сервер}:{_порт}` пишется в SMTP-сокет → чтение

- **Уверенность:** 95%
