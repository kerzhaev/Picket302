Дата: 2026-11-12. Код `63bb970` (фиксы этапа), base `8e474fa` (S16).

прогоне); foreground пользователя не захватывался драйверами (окна
показывались неактивирующе; см. D-S17-03 ниже — единственный случай).

## 2. Найденные дефекты (зарегистрированы этим этапом)

### D-S17-01 (P2, ИСПРАВЛЕН в 63bb970)

«Зафиксировать A4» не обновлял сведения принтера: `ApplyFixA4` переводил
БЛАНК в A4, но `PrinterDeviceInfo` оставался запрошенным под код формата
бланка; на драйверах, сообщающих печатную область меньше бланка, повторная
валидация зацикливалась на блокировке (наблюдался бесконечный цикл
«Конверт слишком большой» → «Проверка размера бумаги» → «Зафиксировать
A4» — 3+ итерации в живом прогоне). Фикс:
`FixA4Mode.ОбновитьПринтерПодФорматA4` + вызов в PrintSessionController;
регрессионные тесты `FixA4PrinterRefreshTests` (3): габариты/область A4 в
обеих ориентациях + валидация бланка A4 проходит. Живой прогон прерван
вручную (пользователь за машиной) — runtime-подтверждение фикса перенесено
в тихое окно.

### D-S17-02 (P1, ИСПРАВЛЕН в 63bb970)

Блокировка кодового штампа (отсутствие шрифта ZIPcode) приходит со статусом
`BlockedSize` — тот же статус, что и блокировка размера бумаги. Оболочка
показывала БУМАЖНЫЙ диалог («Конверт слишком большой…», «Проверка размера
бумаги», «Зафиксировать A4») для НЕбумажной причины: оператору предлагался
путь (фиксация A4), который шрифт не устраняет никогда → вводящий в
заблуждение цикл. Фикс: при `BlockedSize` с причиной ZIPcode бумажный
диалог не показывается; итог уходит в единый маппинг
(`ИзРезультатаКонвейера` → Ошибка → одно сообщение оператору, без
повторных попыток).

### D-S17-03 (P1, ОТКРЫТ — требует тихого окна)

MessageBox «Не найден шрифт ZIPcode…» (заголовок «Печать») в живом прогоне
не закрывался: кнопка ОК не реагировала ни на клики владельца машины, ни на
BM_CLICK драйвера; окно исчезло только после завершения дерева процессов.
Показан из async-продолжения печатной цепочки (ConfigureAwait(true) после
закрытия модального предпросмотра). Подозрение: MessageBox отображается, но
владеющий поток не прокачивает сообщения (состояние закрытия модальной
цепочки). Требует контролируемого воспроизведения в тихое окно (границы:
не беспокоить пользователя повторными зависаниями); до закрытия
интерактивные прогоны печати UI не выполняются.

## 3. Статус критерия S17

«Контролируемое задание действительно создано только в сценарии „Печать“»:
на этом хосте полный happy-path UI→спулер недостижим по внешним условиям —
(а) единственный принтер по умолчанию «Microsoft Print to PDF»
интерактивен (PrintToFile-хук есть, но задание обязано пройти валидацию
шрифта); (б) лицензированный шрифт ZIPcode.ttf отсутствует (лицензия не
подтверждена — правило проекта: не копировать/не регистрировать).
Спулер-часть конвейера доказана на app-уровне (S16). Статус:

```text
UI_TO_SPOOLER_VERIFIED=PARTIAL
  отмена/отсутствие печати в прочих сценариях — доказано (0 заданий);
  продуктовый спулер — доказан (S16);
  UI happy-path — BLOCKED_EXTERNAL (ZIPcode-лицензия + интерактивный
  виртуальный принтер) + D-S17-03 открыт;
```

Правило безопасности этапа: интерактивные печатные прогоны при
пользователе за машиной больше НЕ выполняются (два зависших окна за
сессию); воспроизведение D-S17-03 и подтверждение D-S17-01/D-S17-02
runtime — только в тихое окно по согласованию.
