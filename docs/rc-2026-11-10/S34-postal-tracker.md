# RC S34 — Трекер Почты России: UI (№110)

Дата: 2026-11-14. Base `91ad656` (S33). Функция 110 ТЗ §8.8 — закрыт разрыв
«Сервис покрыт (14 переходов ШПИ), диалога нет» (S01 строка 97). Критерии
приёмки: «интеграционный на тестовом источнике: ШПИ/партия/дата/пункт/
история; состояния „нет данных/ошибка/найдено“».

## 1. Что реализовано

| Слой | Изменение |
|---|---|
| UI | `FormRussianPostTracker`: поля партии (номер/дата отправки/пункт отправки/ШПИ по строке), «Зарегистрировать партию», «Запросить статусы», таблица ШПИ/Статус/Вручено/Дата вручения/Ошибка, строка состояния |
| Wiring | `AppServices.СоздатьТрекерПочтыAsync` — базовый адрес и учётные данные из таблицы параметров (`RussianPost.BaseUrl/Login/ProtectedPassword/ProtectedToken`, пароль/токен — защищённое DPAPI-значение; пустые → ошибка авторизации честно видна в состоянии «Ошибка»); `MainShell`: Сервис → «Трекер Почты России…» |

## 2. Состояния (критерии приёмки)

| Состояние | Тест |
|---|---|
| «найдено» | `Найдено_СтатусыВТаблицеСВручением` — 2 ШПИ, 1 вручение, счётчик в статусе |
| «нет данных» | `НетДанных_ПустойОтветОтСервиса` — пустой items, 0 строк, «Нет данных» |
| «ошибка» | `ОшибкаОпроса_СостояниеОшибкиИУведомление` — error из ответа сервиса, уведомление оператору |
| запрос без партии | `ЗапросБезПартии_Отклоняется` |
| валидация ШПИ | `НекорректныйШПИ_ОтклоняетсяТрекером` (14 знаков), регистрация: `РегистрацияПартии_…` |

Тестовый источник — внедрённый адаптер трекера (`Func<base, request, ct, Task<string>>`),
реальный формат JSON сервиса (`items[]/trackingId/status/delivered/deliveredAt`,
`error`). Урок: `JsonSerializer` экранирует кириллицу в тексте запроса
(`\u041F…`) — фейк-адаптер матчится по ASCII-номерам партий.
