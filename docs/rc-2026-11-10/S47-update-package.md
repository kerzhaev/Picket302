# RC S47 — Скачивание обновлений с проверкой целостности (№163, остаток)

Дата: 2026-11-14. Base `31d8e70`. Закрыт разрыв «Проверка обновлений
покрыта; скачивания нет» (S01 строка 106, часть S47). Критерий:
«подписанный/повреждённый пакет не ставится; откат».

## 1. Что сделано

| Слой | Изменение |
|---|---|
| Манифест | `updates.txt` получил ключ `sha256` — ожидаемый хеш пакета; парсится в `UpdateInfo.ExpectedSha256` |
| Скачивание | `UpdateChecker` — инъекция `_загрузчик` (Func<Uri, ct, Task<Stream>>) для проверок без сети; после загрузки — SHA-256 файла сравнивается с манифестом; несовпадение → повреждённый пакет удаляется (откат частичной установки), путь null |
| Тесты | +4 (`UpdatePackageTests`): целый пакет (хеш совпал, файл байт-в-байт), повреждённый (откат + журнал), манифест без sha256 (обратная совместимость), хеш в поле обновления |

## 2. Критерии приёмки → тесты

| Критерий | Тест |
|---|---|
| подписанный пакет ставится | `ЦелыйПакет_ХешСовпал_ФайлСкачанЦелым` (SHA-256 байт-в-байт) |
| повреждённый не ставится | `ПовреждённыйПакет_ХешНеСовпал_ФайлУдалён` (откат: файл удалён, журнал с причиной) |
| обратная совместимость | `МанифестБезХеша_ОбратнаяСовместимость` |
| манифест → поле обновления | `МанифестОтдаётХешВПолеОбновления` |

## 4. Ограничения

- Целостность — SHA-256 из манифеста updates.txt; криптографическая подпись
  (Authenticode/Ed25519) требует инфраструктуры ключей подписания у
  разработчика — бэклог, вопрос владельцу (ключ подписания).
- Скачивание по HTTP допустимо ТОЛЬКО с проверкой хеша (иначе отклонить —
  на усмотрение владельца; сейчас проверка включается наличием sha256).
