# RC S27 — Пользовательские отчёты: CustomReportManager → UI (№56)

Дата: 2026-11-12. Base `cc4af80` (S26). Функция 56 ТЗ §8.4 («Пользовательские
шаблоны реестров и описей», `Application.Services.CustomReportManager.
RegisterUserReport`) доведена до оператора: менеджер подключён к составу
приложения, добавлен диалог «Пользовательские отчёты», исполнение
пользовательских запросов поверх живой базы, изоляция синтаксических ошибок
в диалоге валидации.

## 1. Что реализовано

| Слой | Изменение |
|---|---|
| Инфраструктура (`SqliteReportDataProvider`) | новый `RunDefinitionAsync(definition, values)` — исполнение произвольного валидированного определения (встроенного или пользовательского) с штатным `QueryValidator` и StrictParametric; `RunQueryAsync` переведён на него (семантика без изменений) |
| AppServices | `МенеджерПользовательскихОтчётов` (корень — `DataDirectory` профиля → `Templates/Reports/User`), `ПоставщикДанныхОтчётов` (поверх открытого соединения сессии) |
| UI (`FormUserReports`) | перечень зарегистрированных отчётов (ListView), регистрация (наименование + .lbk + query.xml), «Проверить», «Изменить запрос…» (невалидный текст НЕ сохраняется), «Данные (предпросмотр)…» (до 50 строк поверх текущей базы), строка статуса |
| MainShell | меню Печать → «Пользовательские отчёты…» |
| Доступность | все кнопки/поля с `AccessibleName`; диалог добавлен в `DialogAccessibilityContractTests` (15-й экземпляр контракта) |
| Харнесс | команды `ADDUSERREPORT имя|пакет|запрос` и `USERREPORTS`; ожидание async-продолжений с прокачкой `DoEvents` (команды исполняются внутри `BeginInvoke`, цикл сообщений не качается — наивный `GetResult()` дал бы дедлок) |

Контракт изоляции (ТЗ §8.4, ф.56): синтаксическая ошибка в query.xml не
бросает исключение наружу — регистрация сохраняет файлы, ошибки возвращаются
списком в `UserReportValidationResult` и выводятся в диалоге валидации;
правка запроса с невалидным XML не записывается на диск (данные не
повреждаются — тест `ПравкаНевалидногоЗапроса_НеСохраняетсяДанныеНеПовреждаются`).

## 2. Тесты (+25)

- `CustomReportManagerTests` (10): копирование пакета/запроса в каталог
  пользователя, повторное имя, отсутствующий файл, недопустимые знаки имени,
  **изоляция синтаксической ошибки**, правка невалидного не сохраняется,
  правка валидного сохраняется, загрузка определения, незарегистрированное
  имя, перечень.
- `UserReportProviderTests` (6): строки живой базы («Клиенты»), IN-список,
  пустой список → пустая выборка, диалект без Sqlite-команды →
  KeyNotFoundException, необъявленный параметр → QueryValidationException,
  значение с SQL-комментарием → строгий параметрический режим.
- `FormUserReportsTests` (9): список, изоляция битого запроса в форме,
  пустое имя, повторное имя, предпросмотр данных живой базы, предпросмотр
  битого — текст ошибки, проверка запроса, текст валидации, доступность
  кнопок. Уведомления подменяются (`УведомитьДляПроверок`) — без модальных
  окон; COM/реестр/принтер не используются.

состояние доказано count=2 в ответах ADDUSERREPORT и listing-файлом.

## 4. Ограничения

- Предпросмотр данных — текстовый, с лимитом 50 строк (объём данных отчёта
  не ограничен на стороне менеджера; лимит — только отображение).
- Печать произвольного макета из .lbk по пользовательскому запросу
  (рендеринг CustomBlank по строкам запроса) — отдельная функция, в №56 не
  входит: менеджер регистрирует и валидирует связку «макет + query.xml»,
  исполнение запроса и предпросмотр данных доступны из UI.
- Диалект пользовательского запроса должен содержать команду Sqlite
  (поставка §10.1); PostgreSQL-вариант сохраняется как есть.
