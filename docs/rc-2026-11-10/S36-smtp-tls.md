# RC S36 — SSL-соединение SMTP (№94)

Дата: 2026-11-14. Base `6818d68` (S35). Закрыт разрыв «None/StartTls/
ImplicitTls реализованы, тестов нет» (S01 строка 94). Критерии: все 3
режима, проверка сертификата, отказы; plaintext ≠ защищённая отправка.

## 1. Локальный TLS-стенд (`SmtpTlsStandTests`)

- **TlsFakeSmtp**: TcpListener-эмулятор с режимами БезTls / StartTls /
  ImplicitTls; самоподписанный сертификат генерируется тестом
  (`CertificateRequest.CreateSelfSigned`; ключ персистируется PFX-реэкспортом
  — SChannel Windows не принимает эфемерные ключи). Диалог — ОДИН конечный
  автомат `ДиалогAsync(поток, tlsСогласован, приветствовать)`: после
  STARTTLS рекурсия поверх TLS-потока БЕЗ повторного приветствия
  (параметризовано — лишняя строка 220 сбивала клиента).
- **Сниффер-прослойка**: TcpListener-транзит между клиентом и сервером,
  записывает байты клиента ДО шифрования (`ОткрытыйТекст`) — прямое
  доказательство «plaintext ≠ защищённая отправка».
- Клиент: `SmtpClientFacade` с `TrustSelfSignedCertificate` +
  `TrustedCertificateFingerprint` (ТЗ: самоподписанные — по решению
  пользователя через отпечаток).

## 2. Тесты (+5)

| Тест | Критерий |
|---|---|
| `ImplicitTls_ЗащищённаяОтправка_PlaintextНеВиден` | TLS с первого байта; сниффер НЕ содержит MAIL FROM/логин/тело; сервер после расшифровки видит полный диалог |
| `StartTls_СогласованиеИЗащита` | EHLO → STARTTLS → рукопожатие → защищённые AUTH/MAIL FROM; сниффер чист |
| `StartTls_СерверБезПоддержки_ОтказБезУтечкиУчётныхДанных` | EHLO без STARTTLS → понятная ошибка, AUTH не отправлялся (сниффер) |
| `ОтпечатокНеСовпал_ОтказСФиксациейОтпечатка` | чужой отпечаток → отказ, фактический отпечаток зафиксирован в `ОтклонённыйОтпечаток` (диалог доверия) |
| `None_ОткрытыйТекстВиденСнифферу` | КОНТРАСТ: тот же трафик без TLS полностью читаем сниффером |

## 4. Ограничения

- Стенд — упрощённый диалог (LOGIN-фолбэк, одно отправление); полный
  клиентский контур (очередь, отмена, повторы) — №100 (S40).
- Сертификат валиден по отпечатку, но CN не совпадает с хостом — проверка
  имени хоста покрывается штатной валидацией цепочки (SslPolicyErrors);
  доверие по отпечатку перекрывает отказ.
