# RC S37 — SMTP-прокси (№95)

Дата: 2026-11-14. Base `30cbadd` (S36; включает S36-фиксы D-S36-01/02).
Закрыт разрыв «HTTP CONNECT реализован, тестов нет» (S01 строка 95).
Критерии: маршрут, авторизация, отказ/таймаут; секреты не в логах.

## 1. Локальный стенд (`SmtpProxyStandTests`)

- **SmtpProxyStand**: TcpListener-прокси — читает CONNECT-запрос (полные
  заголовки в `ConnectЗапросы`), при `авторизация` требует
  Proxy-Authorization, при `отказ` отвечает 403, при `молчать` не отвечает
  (таймаут-сценарий); после 200 — реле на минимальный SMTP-сервер.
- Клиент: `SmtpClientFacade` с `ProxySettings{Enabled, Server, Port, Login,
  ProtectedPassword (DPAPI)}`; пароль расшифровывается
  `ProxySettingsMapper` (ЗащищённыйПароль.Расшифровать).

## 2. Тесты (+4)

| Тест | Критерий |
|---|---|
| `Маршрут_ConnectВедётКSmtpСерверу_ОтправкаУспешна` | F-B2: CONNECT адресует `smtp.example.test:25` (SMTP-сервер, не прокси); отправка успешна |
| `АвторизацияНаПрокси_BasicЗаголовокСРасшифрованнымПаролем` | Proxy-Authorization: Basic = base64(`login:расшифрованный DPAPI-пароль`) — расшифровка фактическая |
| `ОтказПрокси_407_ПонятнаяОшибка` | 407-ответ прокси → «Прокси-сервер отказал в туннеле…» |
| `ТаймаутПрокси_ОграниченноеОжиданиеБезУтечки` | молчащий прокси → ограниченное ожидание (15 с), ошибки не содержат пароль SMTP/прокси |

недоставленными (клиент ждал приветствие и падал по таймауту) — реле
двунаправленный.
