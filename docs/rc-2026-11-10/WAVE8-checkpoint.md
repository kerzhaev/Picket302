Дата: 2026-11-13. Диапазон: base `2f3b20d` → HEAD на момент чекпойнта —
линия S36–S40 и фиксы ревью (`30cbadd`, `6dee3a7`, `d72cc84`, `3ee5931`,

## 1. Функциональные итоги (шесть функций CLOSED + два документа)

| Этап | Функция | Результат |
|---|---|---|
| S36 | №94 SSL SMTP | TLS-стенд: 3 режима (None/StartTls/ImplicitTls), доверие по отпечатку, отказы без утечки учётных данных, сниффер-доказательство plaintext ≠ защищённая |
| S37 | №95 SMTP-прокси | HTTP CONNECT стенд: маршрут F-B2, Basic-авторизация с DPAPI-расшифровкой, отказ 407/403, таймаут-ограничение без утечки секретов |
| S38 | №96/99 MIME+ReplyTo | Захват полного DATA: точные заголовки обеих версий (QP русский / base64 HTML), envelope MAIL FROM=From + RCPT TO точный, Reply-To заголовок |
| S39 | №97 WYSIWYG-редактор | Контракт: 15 команд/санитизация; ОчиститьОпасныйHtml (script/iframe/on*/javascript:), санитизация на Готово/Загрузить; preview рендерит очищенное (F-S39R2-03); UI≡MIME base64 байт-в-байт |
| S40 | №100 SMTP-клиент | Отчёт партии Total/Sent/Failed, журнал записи/получателя, отмена OCE, частичный отказ RCPT 550 персонализирован |
| S41 | №127 клиент-сервер | Архитектурный документ для владельца (варианты A/B/C + формат OWNER_DECISION); S42–S45 ждут решения |

S36-фиксы (2×P3 от ревью S36): дата дока, dispose сертификата стенда.
S37-фиксы (1×P1 + P2/P3 от ревью S37): молчащий прокси держит соединение
(реальный таймаут клиента, assert длительности ≥1,5 с), 403-ветка достижима,
мёртвый код удалён. S38-фиксы (1×P2 + P3): дата, точные пины Reply-To/
Subject encoded-word, QP =3D + ≤76. S39-фиксы (1×P1 + P2 + P3 от ревью
S39): санитизация на Готово/Загрузить + preview рендерит очищенное
(F-S39R2-03), усиление санитизатора (итерации до стабилизации, незакрытые
блоки, on*-обработчики без пробела).

## 4. Открытые вопросы владельца (актуальный перечень)

1. Ратификация OVERALL-эрратума (Волна 2).
2. HKCU/HKLM поставка COM (S15).
3. **№127**: OWNER_DECISION=SQLITE_ONLY / POSTGRESQL / HYBRID_PRO
   (документ S41-db-architecture.md; S42–S45 ждут).
4. **№29 сужение** (D-S32-02): хранение связи в отдельной таблице vs
   mails.incoming_number; встроенный просмотр скана; форма входящих по ТЗ.
5. **№97 остатки** (S39-ревью P3): preview-рендер — IE-движок; санитизатор
   итерационный (5 проходов) — для враждебного входа рассмотреть
   HTML-парсер (HtmlAgilityPack) как бэклог.
6. **№110 остатки**: персистентность партий трекера в памяти диалога;
   ProtectedToken в BuildQueryRequest без DPAPI-расшифровки (задача на
   волну настроек учётных данных).
