# RC S48/S49 — Deferred-обоснования (№14, №125), формы (№163) и чистая машина (S49)

Дата: 2026-11-13. Base `764a458` (S47).

## 1. №14 Поиск по внешней картоте probili.ru — DEFERRED (подтверждение)

Требуется решение владельца о допустимости интеграции с внешним сервисом
(probili.ru — персональные данные, внешний контур, платный API). RC-позиция
без решения: клиента и настроек URL нет в поставке (S8.1), реальный сервис
не вызывается ни одной строкой кода. Обоснование DEFERRED закреплено в
S01-реестре (строка 14, S48); после решения владельца — отдельный этап
(интеграционный тест на согласованном контракте + настройка URL в
Сервис-меню).

## 2. №125 Антиотладка — DEFERRED (подтверждение)

ТЗ §7.4 прямо запрещает перехват отладчика («сознательно: ТЗ запрещает»,
S01 строка 100). Тест `Licensing/AntiDebuggingGuardTests.cs` фиксирует
отсутствие антиотладочных приёмков как соответствие ТЗ. DEFERRED остаётся
с обоснованием запрета ТЗ (S48).

## 4. S49 — Установка на чистую машину

CLEAN_MACHINE_INSTALL_VERIFIED остаётся **NOT_RUN** — для честной приёмки
нужен изолированный чистый контур (ВМ-снапшот без .NET/без профиля
пользователя), которого на станции НЕТ (то же ограничение, что S18/S19).
Что уже покрыто тестами как компоненты установки:

- `UsbInstallerTests` — установка на USB/внешний носитель (копирование базы,
  профиль, запуск с носителя);
- миграции на пустой базе — `MigrationTests`/`MigrationCircularTests`
  (создание схемы с нуля, круг архив/восстановление);
- профильная изоляция — `ProfileIsolationGuard` + `ContainmentIsolationTests`
  (тестовые прогоны не трогают производственный профиль).

**Процедура для владельца** (после получения чистого контура): 1) скопировать
каталог поставки на чистую ВМ; 2) запустить программу; 3) проверить: пустая
адресная книга + демо-база по выбору, печать конверта C6 на виртуальном
принтере, COM-активация, лицензия trial; 4) выставить
`CLEAN_MACHINE_INSTALL_VERIFIED=true/false` с журналом.
