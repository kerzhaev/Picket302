## 1. Группировка строк (№10, [П], была DEFERRED — «GroupableGrid отсутствует»)

**Компонент** `src/Picket302.App/UI/Components/RowGroupingController.cs`:
- группировка несвязанной таблицы адресной книги по колонке («Группа»,
  «Город», «VIP», «Индекс» — любая колонка грида);
- строки одной группы выстраиваются в непрерывный блок (порядок групп — по
  первому вхождению, порядок внутри группы сохраняется), перед блоком —
  строка-заголовок «− Ключ (N)» (полужирная, подсветка);
- клик по заголовку сворачивает/разворачивает блок («+ Ключ (N)» / скрытие
  строк); свёрнутость переживает перестроение (хранение по ключу группы);
- «снятие группировки» возвращает строки в исходный порядок без заголовков;
- выделение сохраняется при перестроении по тегам записей;
- пустой ключ обозначается «(без группы)»; placeholder-строка нового
  элемента (IsNewRow) группировкой не затрагивается;
- текст заголовка группы прорисовывается НА ВСЮ ШИРИНУ строки
  (RowPostPaint; значение в первой ячейке остаётся машинным) — ревью F3;
- свёрнутость группы переживает перестроение, снятие группировки
  восстанавливает исходный порядок строк по снимку идентификаторов —
  ревью F4/F5; навигация поиска отображается на список по
  тегам-идентификаторам, скрытая свёрнутой группой строка разворачивается
  перед показом — ревью F1 (маппинги `СписочныйИндекс`/`СтрокаПоИдентификатору`).

**Интеграция** `MainShell.cs`:
- `_группировкаПолучателей.Подключить(...)` при инициализации таблицы;
- `Перестроить()` в конце каждой загрузки получателей — после сортировки
  (СортировкаИзменена → перезагрузка) и поиска группы пересобираются по
  актуальному составу строк;
- контекстное меню таблицы: подменю «Группировка строк» (Без группировки /
  По группе / По городу / По признаку VIP) с радио-отметкой текущего режима
  (синхронизация при открытии подменю);
- публичные `ГруппировкаПолучателей` / `ЧислоЗаголовковГруппировки` /
  `ПрименитьГруппировкуПолучателей(колонка)` для приёмки.

**Тесты** `App/RowGroupingControllerTests.cs` (10, порядок-независимые,
каждый создаёт собственную таблицу; три добавлены по ревью: маппинг
тегов при группировке, свёрнутость после перестроения, восстановление
исходного порядка при снятии): пустая таблица; вставка заголовков со
счётчиками в порядке строк; пустой ключ; сворачивание/разворачивание;
снятие группировки; перестроение после изменения порядка (группы по новому
порядку); сохранение выделения по тегам. При разработке пойман и исправлен
дефект дизайна первого варианта: строки группы НЕ выстраивались в блок,
если группа была разорвана сортировкой (легаси-поведение — блоки).

## 2. Inline-поиск внутри таблицы

Механизмы поиска уже реализованы интеграцией stage5 и покрыты
`App/SearchMechanismTests.cs` (16 фактов): НайтиДалее (впереди/с текущей/
оборот в конец/нет совпадений/пустой запрос/режимы совпадения/регистр и
формат), прямой набор (отбор по началу строки; пустой набор — пустой
результат), SearchSession (сброс по Esc по одному условию; фильтры
«Избранное» и группы раздельны; редактирование набора), автодополнение
полей. Состояние пустого списка: `НайтиДалее` на пустом списке → −1,
`Совпадения` → пусто; runtime-пустая книга — run-emptybook (COUNTS всего=0).
Поисковая навигация Ctrl+F («Найти далее») при активной группировке
работает через теги-идентификаторы: стартовое смещение и результат
применяются к списку записей, показ — к строке по идентификатору с
авторазворотом свёрнутой группы (ревью F1, тест маппингов).
Взаимодействие с группировкой: поиск перезагружает таблицу → `Перестроить`
пересобирает группы по найденному составу (юнит-покрыто тестом
перестроения; живой сценарий ниже).

## 5. Ограничения

- Одноуровневая группировка (легаси-референс показывает один уровень);
  многоуровневая «настройка и порядок группировки» — по потребности владельца.
- Выбор колонки группировки не персистится между запусками (ТЗ №10 этого не
  требует; №12 о персистентности касается колонок таблицы) — зафиксировано
  как возможное расширение.
- Bold-шрифт заголовков кэшируется и инвалидируется при смене Font таблицы
  (смена кегля в «Настройке вида таблиц»); заменённый экземпляр живёт до
  ближайшего перестроения, так как может числиться в стилях строк (ревью
  S07 F-R3-2/F-R3-4 — утечки устранены, семантика описана).
- `Domain.Rules.GroupHierarchy` (0 покрытия в S05) относится к функции №154
  (циклы дерева категорий), а не к №10 — уточнение к карте рисков S05:
  класс остаётся непокрытым, закрывается тестами №154 в S08+.
