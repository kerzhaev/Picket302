# RC S38 — Формат письма текст/HTML (№96) + Точный ReplyTo/отправитель (№99)

Дата: 2026-11-14. Base `6dee3a7` (S37). Закрыты два разрыва «работает
end-to-end, прямого теста нет» (S01 строки 92 и 94-номинации). Критерии:
«точные envelope/header и содержимое обеих версий»; №99: «MAIL FROM/RCPT TO,
Reply-To есть».

## 1. Стенд (`SmtpMimeTests`)

Сервер-приёмник с захватом **полного тела DATA** (`ТелоПисьма` — MIME-текст)
и **envelope-команд отдельно** (`Envelope` — MAIL FROM/RCPT TO как получены).
Это даёт прямые проверки и заголовков письма, и конверта SMTP.

## 2. Тесты (+4)

| Тест | Проверка |
|---|---|
| `TextPlain_ТочныеЗаголовкиMIMEИТело` | From/To/Subject (RFC 2047 «Subject: =?»)/MIME-Version/Content-Type text/plain; charset=utf-8/CTE quoted-printable; тело раскодируется в исходный русский текст |
| `Html_ФорматBase64СТочнымContentType` | Content-Type text/html + base64 раскодируется байт-в-байт в исходный HTML |
| `ReplyTo_ЗаголовокИEnvelopeТочны` | Заголовок Reply-To присутствует; envelope MAIL FROM — адрес отправителя письма, RCPT TO — точный адрес получателя |
| `БезReplyTo_ЗаголовкаНет_EnvelopeПоОтправителю` | без ReplyTo — заголовка нет; envelope по отправителю |

## 3. Семантика (уточнена тестом, соответствует RFC)

- Envelope MAIL FROM = адрес отправителя письма (From) — обратный путь для
  bounced-писем; Reply-To = заголовок «куда отвечать»,-envelope не касается.
- Вложенные письма: multipart/mixed с границей, кириллические имена файлов
  RFC 2047 (функция 98) — покрыто существующими тестами фасада.

## 5. Ограничения

- Тело письма захватывается построчно (AppendLine нормализует CRLF) —
  точность заголовков и раскодировки проверена; байтовая точность CRLF
  между строками тела — фасадная ответственность (RFC 5321 dot-stuffing
  проверен фасадными тестами).
