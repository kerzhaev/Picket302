Каталог стилей: `DocumentStyleLibrary` (Id/Name/ресурс; `LoadFromResource`).
Каждый стиль преобразует модель `<parameters>` в WordprocessingML
(`w:document/w:body`) для конвейера функции 68 (`ExportToDocx`).

## 2. Валидация каждого файла (тест `DocumentStyleLibraryTests`, +6)

1. **12 XML**: каждый ресурс десериализуется `ReportQueryXmlSerializer`,
   проходит `ValidateDefinition`, содержит команды ОБОИХ диалектов
   (Sqlite обязательна по §10.1).
2. **16 XSLT**: перечень == 16, Id уникальны, ресурс непустой.
3. **Компиляция**: каждый стиль загружается штатным
   `XslCompiledTransform.Load` (настройки по умолчанию — сценарии и
   `document()` запрещены).
4. **Маркеры**: каждый `select="Имя"` стиля присутствует в
   `DocumentMarkerCatalog` (введённые в шаблон маркеры невозможно «потерять»).
5. **Реальная применимость**: каждый стиль рендерится
   `ArbitraryDocumentEngine.Render` с типовой моделью → валидный
   WordprocessingML-документ с `w:body` и подставленными значениями; НОЛЬ
   предупреждений о неразрешённых маркерах.
6. **Независимость от MS Office**: стиль «Напоминание об оплате» через
   `WordprocessingMlExporter.ExportToDocx` → корректный DOCX-пакет
   (`word/document.xml` внутри), подставленные значения на месте; ни OLE,
   ни COM, ни Interop не используются (§8.5, ф.68 DONE-контур).

## 4. Ограничения

- Стили — отправные точки для технолога: редактируются мастером (№66),
  копируются в профиль пользователя при настройке; библиотека только для
  чтения (ресурсы сборки).
- Состав маркеров стилей ограничен карточкой контрагента и адресными
  срезами (словарь полей `to_zip` и т.п.); маркеры рассылок/отправителя —
  по мере появления функций, тест 4 гарантирует отсутствие «мёртвых»
  ссылок в любом случае.
