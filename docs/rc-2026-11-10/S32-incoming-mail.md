# RC S32 — Входящая корреспонденция (№29)

Дата: 2026-11-13. Base `441670a` (S31). Функция 29 ТЗ §8.2 — закрыт разрыв
«только сущность MailDocument; регистрации, сканов, типа и поиска нет»
(S01 строка 79). Критерии приёмки: «создание/поиск/просмотр/удаление
входящего; путь скана в профиле, не теряется при ошибке».

## 1. Что реализовано

| Слой | Изменение |
|---|---|
| Домен | `IncomingMail` (RegNumber уникальный, RegDate UTC, Sender, Subject, `DocType` — Letter/Parcel/Courier/Other, ScanPath → профиль, CreatedAt) |
| Хранилище | миграция `V009__add_incoming_mails.sql` (`incoming_mails`, UNIQUE reg_number, индекс reg_date DESC, `-- Описание:` хедер) |
| Репозиторий | `IIncomingMailRepository`/`IncomingMailRepository`: Add, GetById, Search (LIKE по номеру/отправителю/содержанию, сортировка свежие сверху), Delete |
| Служба | `IncomingMailService`: регистрация с копированием скана в профиль (`scans/`), поиск, просмотр, удаление |
| AppServices | `СлужбаВходящих` (репозиторий поверх сессии + `_профиль.DataDirectory`) |

## 2. Семантика скана (ключевой критерий приёмки)

- Скан копируется в `<профиль>/scans/<timestamp>-<guid>.ext` **ДО** записи в
  базу; запись ссылается на копию в профиле (исходник не тронут).
- **Сбой записи (занятый номер, UNIQUE) не удаляет скан**: обе копии остаются
  в профиле, регистрацию можно повторить с тем же файлом —
  `ОшибкаРегистрации_СканВПрофилеНеТеряется` (пин).
- Отсутствующий файл скана → `FileNotFoundException` ДО записи — журнал не
  содержит записей с битым сканом (`ОтсутствующийСкан_ОшибкаБезЗаписиВЖурнал`).
- Удаление записи журнала файл скана **сохраняет** (документ-основание).

## 3. Тесты (+7, `IncomingMailServiceTests`)

Регистрация/просмотр/поиск (по номеру, отправителю, содержанию)/удаление;
повторный номер отклоняется; скан копируется в профиль; сбой регистрации —
скан жив; битый скан — без записи; без скана — путь пустой. Плюс фикс
`MigrationCircularTests`: 21 таблица после V009.

## 5. Ограничения

- Удалённые записи и неудачные регистрации оставляют копии сканов в
  profiles scans/ без автоматической очистки (осознанно: скан — документ-
  основание); периодическая уборка — бэклог.
- LIKE-поиск в SQLite регистрозависим для кириллицы; спецсимволы %/_ в
  запросе расширяют выборку только в пределах трёх колонок журнала одного
  профиля (инъекции нет — значение привязано параметром).

- UI-диалог входящих отложен в S33 (вместе с движением документов №30 —
  общий интерфейс над журналом); критерии приёмки №29 — интеграционные,
  закрыты тестами.
- Сканов на запись (веб-камера/сканер) нет — скан приносится готовым файлом;
  путь хранится в профиле.
