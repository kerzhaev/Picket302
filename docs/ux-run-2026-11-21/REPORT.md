(evidence приёмочных сценариев), `harness-printconfirm*` (печатные сценарии).

## 2. Реестр находок

### P1 — блокирует основную функцию

**P1-1. ✅ ЗАКРЫТО 21.11.2026 — печать конверта блокировался отсутствующим шрифтом `ZIPcode`.**
Шрифта `ZIPcode.ttf` не было ни в репозитории (ни одного `.ttf`), ни в комплекте
поставки: любая печать с кодовым штампом отменялась сообщением «Не найден шрифт
ZIPcode.», и приёмочные сценарии печати (F5/F7) не завершались.
**Решение принято владельцем:** шрифт взят из комплекта другой программы
(`D:\KonvertProNet\ZIPcode.ttf`, SHA-256 `4e8894433f8995f47e2bedadf4f50ce2837a19c91d61050a7b81bdc7f7ef6518`).
Второй файл из того же комплекта (`ZIPcode2.ttf`) — другой шрифт: его семейство
называется «PrintAdr ZIPcode» (рамки без точечного паттерна), а индекс на
конверте рисуется шрифтом «ZIPcode» (точечный паттерн ОПС) — проверено отрисовкой
обоих, см. ниже.

Что сделано:
- шрифт положен в репозиторий: `src/Picket302.App/Fonts/ZIPcode.ttf`;
- копируется в каталог программы как `Fonts\ZIPcode.ttf` (правило csproj);
- публикация оболочки объявляет шрифт **обязательным** — без него публикация
  падает с ошибкой (fail-closed), пакет без шрифта собрать нельзя;
- установщик ставит шрифт в каталог шрифтов пользователя (`{autofonts}`,
  `FontInstallName: "ZIPcode"`), чтобы гарнитуру видели драйвер принтера и
  предпросмотр;
- **главное исправление — молчаливая подмена шрифта.** Регистрация шрифта в
  сеансе (`AddFontResourceW`) возвращает успех, но GDI+ в том же процессе
  гарнитуру «ZIPcode» **не видит**; `Font("ZIPcode")` молча превращается в
  «Microsoft Sans Serif», и на конверте вместо индекса печаталась пустота
  (это и наблюдал владелец: «ничего нет, тупо белый текст»). Теперь:
  - гард отдаёт **семейство** для отрисовки (`IZipcodeFontGuard.PostIndexFontFamily`):
    системная гарнитура, если шрифт установлен, иначе — семейство из файла
    комплекта поставки (`PrivateFontCollection`), которое видно сразу;
  - `IGraphicsContext` получил перегрузку `DrawStringMm(…, FontFamily, …)`,
    а `PostIndexRenderer` рисует индекс именно этим семейством, а не поиском
    гарнитуры по имени;
  - `EnsureZipcodeFontInstalled()` по-прежнему вызывается при старте (оболочка —
    оба режима, и COM-диспетчер) — для прочих процессов;
- контрактные тесты: `ZipcodeFontSupplyTests` (4 — поставка) и
  `ZipcodeFontRenderingTests` (3 — регрессия подмены: гард отдаёт семейство
  из файла, без шрифта печать заблокирована, индекс рисуется семейством гарда).

**О PDF из приёмочного сценария:** `harness-printconfirm-font3/rc-s17-f5-printtofile.pdf`
почти пуст не из-за дефекта печати, а потому что сценарий печатает по минимальному
подставному шаблону без полей и без кодового штампа. Проверка самого индекса —
`prints/14-printed-envelope-index.png` (конверт с настоящим индексом).

**Проверено глазами:** конверт с индексом напечатан настоящим заданием
(`PrintDocument` → Microsoft Print to PDF) и отрендерен в PNG: на листе —
шесть цифр «101000» шрифтом ZIPcode (рамки с точечным паттерном и верхним
штрихом) и адрес обычным шрифтом. До исправления на этом месте был пустой лист
A4 (803 байта), после — 7806 байт с содержимым.
Тесты: Debug 1829/0/4 и Release 1829/0/4.



### P2 — серьёзные дефекты поведения/интерфейса

**P2-1. Диалог печати всегда выбирает первый принтер в списке спулера.**
Восстановление «последнего принтера» (ТЗ §8.5, функция 35) и принтер по умолчанию
Windows **игнорируются**: `_принтеры.SelectedIndex = 0` выполняется безусловно после
блока восстановления.
Факт: системный принтер по умолчанию — `Microsoft Print to PDF`, а в диалоге
предложен `PDF-XChange 5.0 for ABBYY` (первый в перечислении спулера).
Пользователь печатает не на тот принтер — риск неверного вывода/лотка/формата.
*Основание:* `src/Picket302.App/UI/Forms/FormEnvelopePrint.cs:169-198`;
рис. `harness-printconfirm/21-диалог-печати-f5.png`.

**P2-2. Редактор рассылки: подсказка в правой колонке свёрстана «кашей».**
Текст «Получатели не выбраны. Выделите контрагентов слева и дважды щёлкните…»
разбит по узкой колонке и выглядит как случайный набор слов; он не читается как
инструкция. Ожидается спокойная подсказка под таблицей или всплывающая.
*Основание:* `dialogs/d3-distribution-editor.png`.

**P2-3. Диалог «Регистрация программы» противоречив и не объясняет ограничений.**
Показывает одновременно «Состояние: пробный период закончился» и «Действует до: не
ограничен»; не сообщает, какие функции заблокированы в редакции Free; сообщение
«Пробный период закончился» дублируется; длинный идентификатор оборудования не
копируется одним действием; в статусной строке главного окна то же сообщение дано
без пояснения.
*Основание:* `screens/10-registration.png`, `screens/01-main-address-book.png`.

### P3 — полировка и удобство

**P3-1.** Карточка контрагента: заголовок колонки пользовательских полей читается как
«Тир» — вероятно обрезка «Тип»; требует проверки (`dialogs/d1-counterparty-card.png`).

**P3-2.** Сообщение «Общая база недоступна…» выводится обычной строкой в форме, без
иконки/цвета: при плотной компоновке его легко не заметить (нужен акцент).

**P3-3.** В панели «От кого» заглушка «Справочник отправителей пуст…» соседствует с
заполненной таблицей получателей — читается как противоречие (нужна формулировка
«выберите отправителя для конверта»).

**P3-4.** В редакторе рассылки до выбора получателей нет основной кнопки — только
«Отмена» и счётчик «Всего необходимо конвертов: 0»: диалог выглядит нерабочим.

**P3-5.** Подписи-подсказки в шапке таблицы (мелкий серый текст) трудночитаемы.

## 4. Инфраструктура (не продукт, но мешает приёмке)

1. **Штатный UI-харнесс не собирался на `main`** — `AppServices.Контрагенты`/`Письма`
   удалены волной 1, а драйвер `tools/ui-acceptance` на них ссылался
   (10 ошибок CS1061). Исправлено агентом: переход на `состав.Данные.*`, локальный
   helper сидера, `SetGlobalSender(id)`. **Правка не закоммичена** — решение владельца.
2. **Харнесс печати упирался в чужой принтер.** Сценарий печати требует принтера с
   `PrintToFile` (Microsoft Print to PDF), а приложение выбирало первый в списке
   спулера (`PDF-XChange 5.0 for ABBYY`), который задание в файл не пишет. В драйвер
   добавлен выбор принтера в диалоге печати (Win32 `CB_SETCURSEL`).
   Важная деталь: `CB_SETCURSEL` **без уведомления `CBN_SELCHANGE`** не меняет
   выбор приложения — WinForms держит `SelectedIndex` в собственном кэше. После
   добавления уведомления печать пошла на выбранный принтер, и сценарий стал PASS.
3. **Остаток сценария S5 (блокировка размера бумаги) — среда, не дефект.** Проверка
   идёт против печатной области ВЫБРАННОГО принтера; ни `Microsoft Print to PDF`,
   ни `PDF-XChange` на этой машине не сообщают область меньше 324×229 мм, поэтому
   блокировка не наступает. Сценарий требует принтера с известной малой областью.
4. **Брокер computer-use падает на модальных окнах этого WinForms-приложения**
   («response lost» + рестарт). Для приёмки применялись Win32-снимки и Win32-ввод.
5. **Кросс-процессный WM_SETTEXT/WM_CHAR не обновляет кэш `Control.Text` WinForms**:
   приложение видит пустое поле (ввод в форму сопряжения не сработал, пока
   ввод не сделан с настоящим фокусом). Для честного ввода нужен
   `AttachThreadInput` + `SetFocus` + `SendInput`.

## 5. Открытые вопросы владельцу

1. **Выбор принтера по умолчанию** (P2-1): чинить ли в `FormEnvelopePrint`
   (приоритет: последний использованный → принтер Windows по умолчанию → первый
   в списке)? Из-за этого печать уходит на `PDF-XChange`, а не на принтер
   системы, и проверка размера бумаги идёт против неверного принтера.
2. **Ограничения редакции Free**: перечислить в диалоге регистрации, что именно
   перестаёт работать после пробного периода.
3. Правку UI-харнесса и поставки шрифта — коммитить в `main`? Сейчас не
   закоммичено: `tools/ui-acceptance/Program.cs` (починка API), `run-printconfirm.ps1`
   и `run-screens2.ps1` (выбор принтера), `acceptance-lib.ps1` (общий помощник),
   `run-user-dialogs.ps1` (новый), `src/Picket302.App/Fonts/ZIPcode.ttf` (новый),
   `src/Picket302.App/Picket302.App.csproj`, `src/Picket302.App/AppServices.cs`,
   `src/Picket302.ComAutomation/AutomationDispatcher.cs`,
   `tests/Picket302.Tests/Packaging/ZipcodeFontSupplyTests.cs` (новый),
   `installer/README.md`, `docs/client-installer-2026-11-16/OWNER-GUIDE.md`.

## 6. Как продолжить

Сценарии готовы к повторному прогону: `tools/ui-acceptance/run-*.ps1`
(с `P302_EVIDENCE_ROOT`), новый сборщик диалогов — `run-user-dialogs.ps1`.
После решения по шрифту и принтеру прогон печати (`run-printconfirm.ps1`) должен
завершиться PASS — это и есть критерий готовности к приёмке.
