# Stage3.3 — профильный DI-шов и доступность рабочих диалогов

Дата проверки: 2026-11-09<br>
Статус: `READY_WITH_LIMITATIONS`<br>
Рабочая ветка: `main`<br>
Коммит: локальный коммит серии создан; точный SHA фиксируется в `git log`.

## 1. Цель серии

Серия закрывает два безопасных кодовых хвоста из предыдущего плана:

1. устранить обход изоляции профиля в пункте «Открыть базу…» без изменения
   обычного production-поведения пользователя;
2. распространить контракт доступности на рабочие диалоги, которые ранее не
   входили в runtime-контракт: подключение, импорт, экспорт и архивирование.

Системный реестр COM, физический принтер и системный масштаб Windows в этой
серии намеренно не затрагивались.

## 2. Что изменено

### 2.1. Профильный путь для «Открыть базу…»

- `AppServices` теперь хранит `Picket302ProfilePaths` состава и создаёт
  профильные `ConnectionManager`/`ServerRegistry` для диалога подключения.
- `MainShell.ОткрытьБазу` использует этот seam, когда оболочка создана с
  `AppServices`.
- Для обычного запуска без состава сохранён существующий production-путь
  `%AppData%\Picket302`; перенаправление пользователя, запрет пункта и
  изменение продуктовой семантики не вводились.
- Добавлен regression-тест
  `MainShellConnectionProfileTests.ДиалогПодключения_ИспользуетПрофильПереданногоСостава`.

### 2.2. Доступность диалогов

- `DialogAccessibilityContractTests` расширен с 4 до 8 форм:
  карточка контрагента, карточка отправления, настройка вида таблиц, клипарт,
  подключение, импорт, экспорт, архивирование/восстановление.
- Для кнопок добавлены `AccessibleName` и, где полезно,
  `AccessibleDescription`.
- Контракт покрывает также динамические кнопки скрытых экранов мастера импорта:
  предпросмотр, итоги, применение и диалог создания категории.
- Исправлен диагностический ложный след: одноимённая кнопка `<< Назад` в
  нижней панели мастера уже имела имя; безымянной была другая кнопка
  `<< Назад` внутри экрана предпросмотра.
- Смысл, обработчики, порядок экранов и пользовательский production-flow не
  изменялись.

  проверенная DPI-симуляция 120/144 остаётся отдельным доказательством.
- Источник исторического изменения `picket302.db`/`connection.json` не
  установлен; в этой серии production-профиль не изменялся.
- `graphify-out/` не тронут.

## 5. Следующие ворота плана

1. **Reference/UI gate.** Собрать утверждённую матрицу референсных снимков
   главного окна и рабочих поверхностей и сравнить их с Release-скриншотами.
   До появления референсов статус остаётся `PARTIAL`, а процентное сходство
   не объявляется измеренным.
2. **OS-DPI gate.** На отдельной безопасной сессии или стенде проверить
   Release-приложение при реальном масштабе Windows 125% и 150%, с теми же
   layout/assertion/evidence-проверками. Не делать это скрытой подменой
   пользовательского масштаба без согласованного стенда.
3. **COM gate.** Если владелец отдельно разрешит, выполнить холодную COM-
   активацию в изолированном HKCU/временном registration scope с обязательным
   `CoRegisterClassObject`, вызовами контракта, `CoRevokeClassObject`, кодом
   выхода и полным cleanup. Производственный реестр нельзя считать проверенным
   по одному unit-тесту.
4. **Print gate.** После согласования устройства и лицензии шрифта выполнить
   физический/контролируемый печатный прогон: шаблон, поля, штрихкод, очередь,
   отмена, spooler before/after и отсутствие побочных заданий.
5. **Release gate.** Локальный коммит этой серии создан после review и полной
   non-COM-проверки. Push в GitHub и отдельный PR ещё не выполнялись.
