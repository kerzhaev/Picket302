# «Открыть базу…» — политика пути подключения (stage3.2, 2026-11-09)

```
OPEN_DATABASE_POLICY=PRODUCTION_BEHAVIOR_PRESERVED_WITH_PROFILE_AWARE_DI_SEAM
```

## Факты (read-only аудит, подтверждён в stage3.1 env3-02.md §3)

- При обычном запуске без заранее созданного состава скрытый вход
  `Program.Main` (Program.cs:49) по-прежнему создаёт `new ConnectionManager()`:
  конструктор по умолчанию указывает на production
  `%AppData%\Picket302\connection.json`.
- `MainShell.ОткрытьБазу` сохраняет это production-поведение для обычной
  оболочки, но при переданном `AppServices` создаёт независимые менеджер и
  справочник через profile-aware DI seam. Поэтому оболочка тестового или
  acceptance-профиля больше не пересекается с `%AppData%`.
- Это ПРЕДНАМЕРЕННОЕ производственное поведение (диалог подключения всегда
  оперирует реальным профилем; комментарий в коде фиксирует замысел:
  «реквизиты не должны зависеть от текущей сессии»).
- Acceptance-прогоны этот путь НЕ достигают (диалог «Подключение к базе
  данных» драйверами не открывается); вся цепочка AppServices использует
  ЯВНЫЙ путь профиля.
- Реальная утечка другой природы (реестр SenderId) закрыта в stage3.1
  (`NullCurrentSenderStore` + тесты).

## Что НЕ сделано (без решения владельца)

Запретить пользователю открывать базу, перенаправлять production-пользователя
в temp-профиль или менять семантику production — не выполнялось.

## Что уже добавлено в инфраструктуру (без изменения поведения)

- `GUARD PASS pid+root` в stdout каждого acceptance-прогона;
- `ContainmentIsolationTests.РеквизитыПодключения_ХранятсяТолькоВПутиПрофиля`
  — состав всегда держит реквизиты в явном пути профиля.
- `MainShellConnectionProfileTests.ДиалогПодключения_ИспользуетПрофильПереданногоСостава`
  — профильные пути диалога проверены вместе с записью отдельного
  `servers.ini`; production-профиль для теста не используется.

## Варианты для решения владельца

1. Оставить production-семантику как есть — именно этот вариант выбран для
   `MainShell`: обычный пользователь продолжает работать с `%AppData%`.
2. Запретить или перенаправить production-пункт — не выбрано; это отдельное
   продуктовое решение владельца.
3. Profile-aware DI seam — реализован для `MainShell(AppServices)`, а
   `Program.Main` намеренно оставлен на production-пути.
