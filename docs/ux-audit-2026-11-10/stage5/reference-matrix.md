## 4. Важное расхождение между кодом и evidence

Stage 4 исправил порядок non-activating capture в
`tools/ui-acceptance/acceptance-lib.ps1`: сначала `PrintWindow` с
`PW_RENDERFULLCONTENT`, затем ограниченный `BitBlt` fallback. Однако файл
`../evidence/01-адресная-книга-пустая-1280x720.png`, который сейчас лежит в
рабочем дереве, визуально содержит две строки меню. Поэтому текущий набор
evidence нельзя автоматически считать доказательством чистого
`PrintWindow`-результата. Нужен новый кадр после Stage 4 с журналом:

1. выбранный HWND и PID;
2. способ захвата (`PrintWindow` или явный fallback);
3. SHA-256 PNG;
4. отсутствие foreground/focus shift;
5. отсутствие наложенной подложки.

Свежая пересъёмка теперь сохранена в
`evidence/emptybook-printwindow-1280x720.png` и сопровождается
`evidence/capture-manifest.md`. Она закрывает именно риск наложенной подложки
для пустого состояния. Заполненный главный экран теперь сохранён в
`evidence/current-main-1280x720-printwindow.png`; остальные поверхности и
количественный общий score по-прежнему требуют отдельных пар
`reference -> current`.

Для поиска и архивирования добавлены реальные команды harness `SHOW search` и
`SHOW backup`; для меню добавлены `FILTERMENU`, `QUICKFILTERMENU`,
`PRINTMENU` и `TABLEMENU`, для таблицы — `SHOW tablecolumns` и
`SHOW tableproperties`. Основной `run-screens.ps1` теперь снимает 16
поверхностей вместо 8 и
завершает happy-path только при наличии новых кадров. Повторяемый прогон
2026-11-10 после пересборки App и harness дал `SCREENS PASS`, `exit 0`,
`TreeOk=True`, `killed=False` и production delta `0/0/0`.

## 5. Подтверждённые visual gaps для следующего UI-этапа

Это уже не предположения по старым отчётам, а расхождения между двумя
зафиксированными парами изображений:

1. **Быстрый фильтр (P2/UI, структурно закрыт):** Picket302 теперь показывает
   `Избранные`, `Все категории` и реальные категории в общем dropdown, а
   текущая система saved filters сохранена ниже. Реальная кнопка `Фильтры…`
   над таблицей открывает этот dropdown и закрывает прежний placement-gap;
   остаются только тонкие отличия точных размеров, отступов и funnel-иконки.
2. **Меню печати (P2/UI, частично закрыт):** F5/F6/F7/F8 и иконки действий
   теперь видны в обоих меню. Оставшееся расхождение — плотность строк и
   стилистика векторных значков против legacy bitmap; это визуальная тонкая
   настройка, а не потеря функции.
3. **Диалог поиска (P2/UI, основная структура закрыта):** legacy имеет поля
   «Образец», «Поиск в», «Совпадение», «Просмотр» и чекбоксы; Picket302 теперь
   имеет те же семантические поля и функционально передаёт выбранные параметры
   в `SearchMechanism`. Runtime-кадр и strict accessibility-контракт зелёные.
   Осталось закрыть inline-поиск и тонкую pixel-level настройку, а не базовую
   структуру/функцию диалога.
4. **Настройка таблиц (P2/UI, основные вкладки закрыты):** columns и
   properties теперь имеют реальные current-кадры и поведенческие тесты.
   Остался current-кадр открытого контекстного меню таблицы и проверка
   сохранения после перезапуска; общий visual score по этой поверхности не
   объявляется.

## 5. Правила дальнейшей оценки

- Не запускать legacy EXE для получения новых кадров: локальные CHM-assets уже
  дают первичный reference без вмешательства в печатный конвейер.
- Не смешивать размер/масштаб bitmap-референса с размером текущего окна.
  Сначала сравнивать композицию, иерархию, подписи, состояния и обрезание;
  затем — относительные расстояния в нормализованных координатах.
- Для каждой поверхности хранить пару `reference -> current`, дату, SHA-256 и
  метод захвата.
- Не выдавать общий процент 70, пока не покрыты хотя бы главный экран,
  предпросмотр, печать, адресный поиск/фильтры, логотип и настройки таблицы.
- `COM_VERIFIED`, `COLD_COM_ACTIVATION_VERIFIED`, `PRINT_VERIFIED`,
  `OS_DPI_125_150_VERIFIED` и количественный общий visual score остаются
  отдельными флагами и не выводятся из этой матрицы автоматически.
