# Установщик серверной части Picket302

Источники установочного пакета серверной службы совместного режима.

## Состав

| Файл | Назначение |
|---|---|
| `picket302-server.iss` | Сценарий Inno Setup 6: публикация файлов, регистрация службы, правило брандмауэра, корректное удаление с сохранением данных. |
| `first-run.ps1` | Локальная консоль администратора: проверка здоровья службы и выдача одноразового кода сопряжения с отпечатком сервера. |

## Сборка пакета

1. Опубликовать службу:

   ```
   dotnet publish src/Picket302.Service -c Release -r win-x64 --self-contained false
   ```

   Публикация складывается в `src\Picket302.Service\bin\x64\Release\net8.0-windows\win-x64\publish`:
   каталог вывода MSBuild содержит имя платформы (`x64`), потому что
   `Directory.Build.props` задаёт `Platform=x64` для всех проектов решения.
   Если публикация выполнена с иным значением `Platform`, путь передаётся
   компилятору параметром (см. ниже).

2. Собрать пакет Inno Setup 6:

   ```
   ISCC installer\picket302-server.iss
   ```

   Либо с явным путём публикации:

   ```
   ISCC /DPublishDir="..\src\Picket302.Service\bin\Release\net8.0-windows\win-x64\publish" installer\picket302-server.iss
   ```

   Результат — `dist\picket302-server-setup.exe`.

**Статус (волна 2026-11-15): INSTALL_BUILD_VERIFIED = true (сборка пакета),
установка — NOT_RUN.** Пакет собран (Inno Setup 6.7.3, .NET SDK 8.0.420,
публикация `win-x64` framework-dependent); SHA-256 пакета приведён в
итоговом отчёте волны. Чистая установка в отдельной ВМ не выполнялась:
виртуальной машины в контуре нет (CLEAN_VM_INSTALL_VERIFIED = NOT_RUN),
реальный SCM и перезагрузка не проверелись (SCM_RUNTIME_VERIFIED = NOT_RUN,
REBOOT_VERIFIED = NOT_RUN).

## Что делает установщик

1. Публикует файлы службы в `{autopf}\Picket302 Service`.
2. Создаёт каталог данных `{commonappdata}\Picket302\Service` (база,
   шаблоны, копии) **без выдачи прав группам пользователей** — каталог не
   является профилем сотрудника и не находится рядом с EXE. При каждом
   старте служба сама ограничивает права каталога и всех вложенных
   объектов (полный доступ — SYSTEM, Администраторы и фактическая учётная
   запись службы) и **отказывается запускаться с кодом выхода 4**, если
   ограничить или проверить права не удалось. Право `users-modify`,
   выданное прежней версией установщика, убирается при первом старте.
3. Регистрирует службу `Picket302Service` (`--install`): автозапуск,
   учётная запись `NT AUTHORITY\NetworkService` (минимальные права, не
   LocalSystem), переживает выход сотрудника из учётной записи.
   **Повторная установка (обновление) поддержана:** `--install`
   перенастраивает уже зарегистрированную службу на новый путь к
   исполняемому файлу, а не создаёт вторую и не завершается отказом.
4. Добавляет правило брандмауэра для входящего TCP 30242 (профиль частных
   сетей). **Нестандартный порт** (из `service.json`) требует отдельного
   ручного правила — автоматическая настройка брандмауэра под него не
   поддерживается и не проверялась:

   ```
   netsh advfirewall firewall add rule name="Picket302 Service (порт 30243)" dir=in action=allow protocol=TCP localport=30243 profile=private
   ```

5. Запускает службу и дожидается её состояния. Проверку здоровья и выдачу
   кода сопряжения выполняет консоль первого запуска (`first-run.ps1`).

Отмена и неуспешная установка не оставляют наполовину созданную службу:
регистрация выполняется самоустановкой исполняемого файла, у которого
`--install` возвращает ненулевой код при сбое. **Коды возврата проверяет
установщик:** при отказе регистрации он снимает регистрацию и прерывает
установку с понятным сообщением; при отказе правила брандмауэра — тоже
прерывает установку; неудачный запуск службы (например, без сертификата
сервера) **не выдаётся за успех** — установщик сообщает состояние службы и
причину и указывает, что делать дальше.

## Что делает удаление

1. Останавливает службу и дожидается её остановки.
2. Снимает регистрацию службы (`--uninstall`). Отсутствие службы
   считается выполненным (повторное удаление не считается ошибкой).
3. Удаляет правило брандмауэра.
4. **Сохраняет** каталог данных `{commonappdata}\Picket302\Service` (база,
   шаблоны, копии) и явно сообщает об этом оператору.

## Подготовка сертификата (до установки)

Служба работает только по TLS: без сертификата сервера она не запускается
(код выхода 2 — ожидаемое поведение, секрет устройства не передаётся по
открытому каналу). Установщик сертификат не создаёт; до установки нужно
от имени администратора на серверном компьютере:

1. Создать самоподписанный сертификат в хранилище компьютера и указать
   его отпечаток в `%ProgramData%\Picket302\Service\service.json`:

   ```powershell
   $cert = New-SelfSignedCertificate -Subject "CN=Picket302 Service" `
       -KeyAlgorithm RSA -KeyLength 3072 -CertStoreLocation Cert:\LocalMachine\My `
       -NotAfter (Get-Date).AddYears(10)

   New-Item -ItemType Directory -Force "$env:ProgramData\Picket302\Service" | Out-Null
   [ordered]@{
       Port = 30242
       CertificateThumbprint = $cert.Thumbprint
   } | ConvertTo-Json |
       Set-Content "$env:ProgramData\Picket302\Service\service.json" -Encoding UTF8
   ```

2. Разрешить учётной записи службы (`NETWORK SERVICE`) чтение закрытого
   ключа (файлы машинных CNG-ключей — в
   `C:\ProgramData\Microsoft\Crypto\SystemKeys`):

   ```powershell
   $key = [System.Security.Cryptography.X509Certificates.RSACertificateExtensions]::GetRSAPrivateKey($cert)
   icacls ("C:\ProgramData\Microsoft\Crypto\SystemKeys\" + $key.Key.KeyUniqueName) /grant "NETWORK SERVICE:(R)"
   ```

**Внимание:** пакет установки **собран** (Inno Setup 6.7.3), но
**установка не выполнялась** на реальной машине:
`CLEAN_VM_INSTALL_VERIFIED = NOT_RUN` (чистой ВМ в контуре нет),
`WINDOWS_SERVICE_VERIFIED = NOT_RUN`, `REBOOT_VERIFIED = NOT_RUN` (окна
обслуживания для перезагрузки не согласовывалось). Приведённые команды
подготовки сертификата на реальной машине не выполнялись. После установки
проверьте, что служба стартовала, и выполните консоль первого запуска —
она сама закрепляет сертификат при подключении.

## Первый запуск и сопряжение

На серверном компьютере выполнить `installer\first-run.ps1` (порт и
отпечаток сертификата берутся из `service.json`; если каталог данных
службы перенесён из `%ProgramData%\Picket302\Service`, укажите его
параметром `-КаталогДанных <путь>`):

1. Проверяет здоровье службы (`/api/v1/health`) по HTTPS с закреплением
   сертификата: принимается ровно тот сертификат, отпечаток которого
   указан в `service.json`; доверия «любому сертификату» нет даже у
   локальной консоли.
2. Выдаёт одноразовый код сопряжения (действует ограниченное время и ровно
   для одного подключения; код нельзя получить удалённым запросом —
   служебные маршруты доступны только с локального адреса и с
   административным токеном).
3. Показывает отпечаток открытого ключа сервера для сверки на клиенте.

На клиенте: «Сервис → Общая база…» — адрес сервера, порт, код сопряжения.
Клиент сверяет фрагмент отпечатка сервера с сертификатом службы и сохраняет
секрет устройства в защищённое хранилище Windows (DPAPI).
