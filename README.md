# Picket302

Настольное Windows-приложение для подготовки, вёрстки, верификации, массовой печати
и регламентного учёта почтовых отправлений, стандартных конвертов, сопроводительных
бланков и реестров.

Требуемые документы: `SPEC_INPUT/IMPLEMENTATION_SPEC.md` (техническое задание),
`00_FUNCTION_INDEX.txt` (перечень 163 функций с приоритетами),
`EVIDENCE/` (подтверждающие выжимки, только для чтения).

> **Состояние репозитория — этап S8 (финальный, интеграционный).** Реализованы все
> слои решения, движок печати, отчёты, экспорт/импорт, COM-сервер автоматизации,
> лицензирование, почта и администрирование. Сквозной приёмочный сценарий и таблица
> покрытия 163 функций — `docs/ACCEPTANCE.md`. Карта слоёв и правила зависимостей —
> `docs/ARCHITECTURE.md`. Принятые допущения — `docs/OPEN_QUESTIONS_LOG.md`.

## Требования

- Windows 10/11 x64;
- .NET SDK 8.0.100 или новее (требования зафиксированы в `global.json`,
  допускается любой патч уровня 8.0.x);
- Visual Studio 2022 (17.x) — для разработки; сборка из командной строки не требует VS.

## Сборка

```powershell
dotnet restore Picket302.sln
dotnet build Picket302.sln -c Debug --nologo -v q
```

Сборка всех проектов решения выполняется в конфигурации `Debug` (или `Release`)
и в платформе `x64`; выходные файлы — `bin\x64\<Конфигурация>\...`.

### Библиотека типов COM-сервера

Файл `PrintEnvelopePro.tlb` (версия 2.2) собирается из описания
`src/Picket302.ComAutomation/idl/PrintEnvelopePro.idl` компилятором MIDL из состава
Windows SDK:

```powershell
powershell -ExecutionPolicy Bypass -File tools\build-typelib.ps1
```

Готовый файл уже лежит в `src\Picket302.ComAutomation\idl\` и копируется в каталог
сборки COM-сервера правилом `CopyToOutputDirectory`; пересобирать его нужно только
при изменении контракта IDL.

## Запуск приложения

```powershell
dotnet run --project src\Picket302.App\Picket302.App.csproj
```

Либо напрямую: `src\Picket302.App\bin\x64\Debug\net8.0-windows\Picket302.App.exe`.
При старте открывается главное окно оператора со строкой меню
«Файл / Правка / Вид / Сервис / Печать / Рассылки / Справка» (ТЗ §7.1).

## Первый запуск

1. База данных создаётся автоматически по пути `%AppData%\Picket302\picket302.db`
   (профиль пользователя); схема разворачивается встроенными миграциями
   `src/Picket302.Infrastructure/Data/Migrations/Sqlite/`.
2. Если адресная книга пуста, база наполняется **демо-данными**
   (`DemoDatabaseSeeder`): 6 контрагентов и категории «Неразобранные» (по умолчанию),
   «Поставщики», «Получатели», «Архив». Это позволяет освоить программу без ввода
   данных. Демо-база не создаётся повторно, если адресная книга не пуста.
3. Очистить демо-данные: меню «Сервис» → «Очистить данные» (`FormClearDatabase`),
   очистка выполняется по типам данных.

Состав демо-базы, категории и порядок сидирования проверяются тестами
`tests/Picket302.Tests/Application/DemoAndCategoriesTests.cs` и приёмочным сценарием
`tests/Picket302.Tests/Acceptance/AcceptanceScenarioTests.cs`.

## Работа оператора: основные возможности

- **Адресная книга.** Сортировка по любой колонке — клик по заголовку столбца
  (повторный клик меняет направление); сохранённые пользовательские фильтры —
  меню «Вид» → «Фильтры» («Сохранить фильтр…», «Применить фильтр…»,
  «Удалить фильтр…», «Сбросить сортировку»).
- **Настройка вида таблиц.** Меню «Вид» → «Настройка вида таблиц…»: цвета,
  показ заголовков столбцов, «полосатая таблица» глобально; состояние столбцов
  (показ, подписи, ширина) сохраняется отдельно для каждой таблицы и
  восстанавливается при следующем запуске; сброс к умолчаниям — «Вид» →
  «Настройка вида таблиц…» → «Сбросить».
- **Скрытие столбцов.** Контекстное меню заголовка таблицы адресной книги:
  «Скрыть столбец» и «Показать все столбцы»; скрытое состояние сохраняется
  сразу. Ручное сохранение состояния столбцов — «Вид» → «Настройка таблицы…».
- **Карточка отправления.** Перед печатью открывается карточка: категория
  отправления (простое письмо / заказное письмо / бандероль с объявленной
  ценностью / 1-й класс), вид уведомления (не требуется / ф.119 (РФ) /
  национальная форма / ф.112эп), флажок «нужно уведомление о вручении»,
  формат конверта и число экземпляров. Значения записываются в отправление
  до печати и попадают в журнал печати и реестр ф.103.
- **Редактор бланков (F8).** Меню «Макет» → «Стандартная разметка» (расстановка
  адресных полей и кодового штампа по нормативным зонам) или «Без стандартной
  разметки (поля вручную)».
- **Импорт адресов.** Форматы TXT, CSV, HTML, RTF, XLS, XLSX — мастер импорта
  адресной книги («Данные» → «Мастер импорта адресной книги…»).
- **Пробный период.** Срок 10 дней и лимиты объёма применяются при создании
  записей и печати партий: при исчерпании оператор получает сообщение с числом
  оставшихся дней; в строке состояния — индикатор остатка дней; при старте
  показывается NAG-экно пробного периода.

## COM-сервер автоматизации

Сервер работает out-of-proc, ProgID `PEPro.Application`; регистрация выполняется
в ветке `HKCU\Software\Classes` и не требует прав администратора.

```powershell
# регистрация
src\Picket302.ComAutomation\bin\x64\Debug\net8.0-windows\Picket302.ComAutomation.exe --register

# снятие регистрации
src\Picket302.ComAutomation\bin\x64\Debug\net8.0-windows\Picket302.ComAutomation.exe --unregister
```

Пример вызова из скрипта — `docs/EXAMPLES.md`, пример макроса для Excel —
`docs/ExcelCallExample.bas` (поставляется как исходник: книга с внедрённым VBA
не может быть собрана без установленного MS Office — допущение S6.5).

## Известные ограничения

Полный перечень с привязкой к функциям и допущениям — `docs/ACCEPTANCE.md`
(раздел «Ограничения») и `docs/OPEN_QUESTIONS_LOG.md`. Кратко:

1. **СУБД — только SQLite.** Эквивалент миграций для PostgreSQL и клиент-серверный
   режим с общей БД отложены: пакет `Npgsql` не подключён (допущения S2.8, О.2, S8.9).
2. **Стендовая печать не выполнялась.** Проверка печати выполнена на мок-DEVMODE
   с детерминированными метриками. Сверка ±1 мм на трёх физических принтерах
   (A4, лотковый конвертный, термопринтер) — критерий приёмки №1 — требует
   оборудования заказчика.
3. **Шрифт ZIPcode.** Лицензия на распространение `ZIPcode.ttf` не подтверждена;
   при отсутствии шрифта в системе печать кодового штампа блокируется явным
   предупреждением, а не подменой обычного шрифта (допущение S4.6, ТЗ §13).
4. **Словарь валют Казахстана пуст** — поставляется пустой шаблон `.lng`
   (допущение S7.7, ТЗ §13).
5. **HTML-редактор писем** — собственный компактный редактор, а не TinyMCE
   (допущение S7.2).
6. **Антиотладка и антимониторинг не реализованы** намеренно; шифрование данных
   лицензии выполняется AES-256-GCM (допущение S7.4).
7. **Диалог первого запуска** (`FormFirstRun`) реализован как форма, но не вызывается
   при старте: демо-база наполняется автоматически при пустой адресной книге,
   а архивирование настраивается отдельным диалогом (функция 163 — частично).
8. **Совместимость с файлами шаблонов предшественников (.fr3) не обеспечена** —
   перенос выполняется экспортом данных и новыми пакетами `.lbk` (ТЗ §13).

## Правила оформления кода

- C# 12, .NET 8, Windows x64;
- `nullable` включён, `ImplicitUsings` включён;
- интерфейсные строки, сообщения домена и комментарии предметной области — на русском языке;
- версии пакетов указываются только в `Directory.Packages.props`;
- тесты — xunit, имена тестов на русском языке.
